# GUI 与右键菜单

> zpack 的图形界面（`ui/gui/`）与文件管理器右键菜单（`ui/right-click/`）：都是经 CLI 二进制 stdout JSON 契约驱动引擎的「启动器」。最后核对日期：2026-11-24（对应提交 `40fb9e7`）。

这份 spec 是该功能的**行为与设计的权威说明**。代码与 spec 不一致时：spec 是有意修改的，改代码；spec 过时了，先修 spec。
每条规则都以代码为准核对过；拿不准的标了「【待确认】」。

## 1. 功能定义

本功能由两个入口组成，共同点是**自己不含任何引擎代码**，全部工作都交给 `zpack` 命令行二进制：

| 入口 | 位置 | 形态 | 现状 |
|---|---|---|---|
| GUI | `ui/gui/` | 单窗口多页桌面应用（mygo 框架，独立 Go module） | 三平台共用一套代码；mac 有装机脚本，Windows 只有构建产物 |
| 右键菜单 | `ui/right-click/macos/` | macOS Finder 的「zpack ▸」菜单（FinderSync 扩展）+ 快速操作三服务 | 仅 macOS；Windows Explorer / Linux 文件管理器未做 |

### 1.1 做什么

- **GUI**：把 CLI 的常用命令铺成 24 个页面——压缩台、解压台、刻录光盘、归档浏览、视频 / 音频 / 图片 / PDF / Office 的转换与压缩、生成密钥 / 加密 / 解密 / Base64 / 文件哈希 / 随机生成，外加多任务处理台和设置页。用户拖入文件、改几个参数、点主按钮，任务在处理台里显示进度，可以取消，完成后能在文件管理器里定位产物。
- **GUI 调引擎的方式只有一种**：起一个 `zpack` 子进程，回读 stdout 上的那一条 JSON，顺带解析 stderr 里的进度行（`ui/gui/service.go` 是唯一通道，ui/gui/main.go:11）。
- **右键菜单**：在 Finder 里对选中项右键 →「zpack ▸」→ 压缩为 ZIP / 压缩为 TAR.GZ / 解压到此处 / 测试归档。菜单项按选中物的真实内容（魔数）动态出现；动作由宿主 app 跑内嵌的 `zpack` 并弹原生进度窗。

### 1.2 不做什么

- **不直连引擎的 Go 包**（`core` / `image` / `pdf` / `media` …）。`ui/gui/go.mod` 只依赖 mygo 及其间接依赖（ui/gui/go.mod:7-21）。GUI 里仅有的一点点「自己算」都是纯展示用的辅助逻辑：读文件头判类型、数 `.001/.002…` 分卷、异步求目录体积、算同名序号——这些不是引擎能力。
- **不抢引擎的格式裁判权**：GUI 侧的格式守卫只拒收「明确认识」的错族文件，认不出的一律放行，由引擎判格后把结论浮出来（ui/gui/sniff.go:3-6）。
- **不暴露 CLI 的全部旗标**，每条命令只摆最常用的一组（第 3.3 节的表里有「GUI 未暴露」一列）。
- **不调用这些命令**：`convert`（归档格式转换）、`bench`、`skill`、`json`、`ffmpeg` 代理、`media` 的 bake / 旋转 / info / preset / 截图族、`audio info`、`image` 的旋转 / 镜像 / 翻转 / resize / info / merge、`pdf info`。
- **不做**：Windows Explorer / Linux 文件管理器右键菜单；菜单栏常驻、Dock 拖放压缩对话、桌面悬浮窗（DESIGN.md §0 / §2 有设计，代码里没有）；参数记忆（设置页底部自己写明「后续版本交付」，ui/gui/main.go:4952）。

### 1.3 使用场景

- 不记命令行的人：拖一个文件夹进窗口 → 保留默认参数 → 点「创建压缩包」。
- 要给特定用途裁体积的人：视频压到 25MB、图片压到 100KB、PDF 只留第 1–3 页。
- 在 Finder 里顺手做事的人：选中几个文件右键压缩，弹窗显示进度与结果。
- 引擎出问题时的排查入口：设置页显示引擎版本与实际使用的引擎路径，点一下可复制。

### 2.3 输入方式通则

- **拖放**：16 个页面把整个内容区当拖放区（上表「接收整页拖放」）。拖入分派在 `pane`（ui/gui/main.go:655-698）。加密 / 解密页不设整页拖放，输入文件字段与钥匙字段各自成拖放区，拖到哪个字段就填哪个，拖悬时字段亮品牌蓝描边（`toolFileField`，ui/gui/main.go:1879-1882、1926-1928）。
- **选择**：一律走系统文件对话框 `mygo.Dialog.Open`。对话框必须在 goroutine 里发起，结果经 `mygo.RunOnMain` 回到主线程（原因见第 6.6 节）。单选 / 目录 / 多选三种形态分别由 `toolBrowse`、`toolBrowseMany` 与各页自带的 `browseXxx` 封装（ui/gui/main.go:875-987、2111-2141）。
- **多选文件对话框在 macOS 上选不到文件夹**（依据是刻录页的注释「Finder 多选不含文件夹」，ui/gui/main.go:5597；Windows 上未核对，【待确认】）。文件夹靠拖入；刻录页因此单独给了「选择文件夹…」按钮，压缩台没有对应按钮。
- **粘贴**：文本域与可编辑输入框都支持——加密 / 解密的文本态、Base64 输入、保存位置 / 解压位置 / 输出位置这类路径框，以及码率、页码、期望值等参数框。路径框里粘进来的换行符会被剥掉（路径里进换行就是坏路径，ui/gui/main.go:1254-1257、4706-4709）。转换族的「输入文件」字段是只读展示（`toolFileField` 里是 `ui.Text`，ui/gui/main.go:1908），不能往里粘贴，只能拖入或点「选择」。
| - **格式守卫**（`rejectIfForeign`，ui/gui/sniff.go:138-145）：单文件输入的页面在落位前读文件头判类型，认出属于**别的已知族**才拒收并 toast「格式不支持：<文件名>」；认不出或同族则放行。无守卫的入口：压缩台（什么都能压）、刻录清单、解压台、归档浏览（这两个改由引擎 `info` / `list` 的结论说话）。清单类入口（PDF 合并、图片压缩）按同样规则逐件过滤并 toast「已跳过 N 个非 XX 文件」。各页要求的类型见 4.4。

### 2.4 压缩台（默认首页）

`pageCompress`，ui/gui/main.go:1165-1605。

- **输入**：整页拖放，文件与文件夹混拖，全量加入；hero 与引导行上的「浏览选择…」开多选文件对话框。入列时剥掉尾斜杠（Finder 拖目录的路径带尾 `/`）、去重保序（`addInputs`，ui/gui/main.go:5438-5457）。没有格式守卫。
- **清单**：单张卡片里的列表，可拖拽排序（框架 `ui.List` + `ListState.Reorder`）。每行 = 类型图标（文件蓝、文件夹琥珀）+ 完整路径（放不下就换行，不截断）+ 尺寸槽。尺寸槽平时显示体积（等宽字体 12px）；鼠标悬停这一行时体积淡出、红色减号徽章滑入（110ms），徽章悬停放大、按下下沉（`inputListRow`，ui/gui/main.go:5295-5369）。减号的语义是「移出清单」，不是删除文件。目录的体积是异步算的：先显示「文件夹」，后台遍历时显示「计算中」，算完换成体积（ui/gui/main.go:5318-5328、5182-5253）。
- **引导行**：`已准备的压缩归档 N 项共 <体积>，可拖拽加入或` +「浏览选择…」。目录在体积算完之前不计入总数。
- **参数区**（开放式两列行：左列 84px 标签 + 12px 副标，右列控件）：

| 行 | 副标 | 可调内容 | 对应旗标 / 作用 |
|---|---|---|---|
| 保存位置 | 默认为文件旁 | 可输入、可点「选择」；留空 = 首输入所在目录 | 决定 `--output` 的目录 |
| 新压缩包名字 | 后缀随格式 | 名字输入框 + 右侧后缀下拉 `.zip` / `.7z` / `.tar.gz` / `.tar`（缺省 `.zip`）；名字留空 = 首输入去扩展名 | 决定 `--output` 的文件名与写格式 |
| 完成后 | 任务成功的动作 | 无动作（缺省）/ 打开文件夹 | 不传引擎；任务成功后打开产物所在目录 |
| 高级设置（默认折叠） | 已启用 N 项 | 压缩级别、添加密码、分卷压缩，见下 | — |

- **高级设置**：折叠卡，头行整行可点开合。折叠且有生效项时头行提示「已启用 N 项」（生效项 = 加密、分卷 ≠ 不分卷、级别 ≠ 6，ui/gui/main.go:1321-1335）。

| 行 | 可调内容 | 对应旗标 |
|---|---|---|
| 压缩级别（0 最快 · 9 最小） | 滑杆 0–9 整数，缺省 6 | `--level N` |
| 添加密码（保护压缩包内容） | 下拉「无密码 / 加密」+ 加密态出密码框与眼睛钮；**只在后缀为 `.zip` 或 `.7z` 时出现** | `--password <值>` |
| 分卷压缩（切分成多个小包） | 下拉：不分卷（缺省）/ Gmail · 25MB / 邮箱 · 50MB / 微信 · 1GB / VCD 刻录 · 700MB / DVD 刻录 · 4.7GB / 自定义；自定义时出输入框（如 300MB / 2GB） | `--volume-size <值>`（预置项原样直传 `gmail`、`50MB`、`1GB`、`cd`、`dvd`） |

分卷行下方有一句后果提示：不分卷时「仅产生 1 个压缩包」，否则「超过 <单卷大小> 自动切为多卷（.001、.002…）」。自定义尺寸填错时这句提示换成红色错误文案，同时主按钮置灰（ui/gui/main.go:1169-1173、1457-1476）。

- **主行动**：`[取消压缩]` `[创建压缩包]`。
  - 取消 = 清空清单、名字、保存位置、密码、分卷设置，回到空态；压缩级别、「完成后」、后缀格式保留（ui/gui/main.go:1571-1581）。
  - 创建 = 起压缩任务并切到处理台。
- **默认值跟随规则**：名字与保存位置在用户没亲手改过之前，随清单变化自动跟随首输入；改过之后就不再跟随（`nameDirty` / `outDirDirty`，ui/gui/main.go:5275-5282）。名字里如果敲了后缀（比如「报告.zip」），后缀会被剥掉——扩展名恒由格式下拉决定（ui/gui/service.go:287-291）。
- **产物**：`<保存位置>/<包名>.<格式>`；已存在则自动加序号 `名字 2.zip`、`名字 3.zip` …（`uniquePath`，ui/gui/service.go:454-467）。
- **密码只存在内存里**：不落盘、不写日志；点「取消压缩」时清空（清单增减不影响它）。
- **GUI 没暴露的压缩旗标**：`--exclude`、`--jobs`、`--temp-dir`、`--comment`、`--comment-file`、`--password-table`、`--quiet`。

### 2.5 解压台

`pageExtract`，ui/gui/main.go:1608-1813。

- **输入**：整页拖放取首件，或「浏览选择…」单选。可以是 `.001` 分卷首卷。
- **归档卡**：图标 + 完整路径 + 尾槽（体积；分卷集显示「共 N 卷」）+ 悬停浮现的移除徽章。
- **体检行**：选定归档后异步跑 `zpack info`（`Inspect`，ui/gui/service.go:534-582）。等待时显示「识别中…」，成功后是 `大写格式 · N 个文件 · 解压后 <体积>`，分卷再加 `· 共 N 卷`，加密再加 `· 已加密`；失败时显示 `<引擎 error_info>，仍可尝试解压`。换归档会重置密码与解压位置；体检回来之前换了归档，过期结果丢弃（ui/gui/main.go:944-964、1689-1709）。分卷数不是引擎给的，是 GUI 自己数同基名的 `.001/.002…`（ui/gui/service.go:586-605）。

| 行 | 副标 | 可调内容 | 对应旗标 |
|---|---|---|---|
| 解压位置 | 默认为归档旁 | 可输入、可点「选择」；留空 = 归档所在目录 | `--output <目录>`（**恒传**） |
| 解压密码 | 归档已加密 / 仅加密归档需要 | 密码框 + 眼睛钮；常驻（不因体检结果而隐藏） | `--password <值>`（非空才传） |
| 完成后 | 任务成功的动作 | 与压缩台共用同一个设置 | — |

- **主行动**：`[取消解压]`（清空选档，回空态）`[解压]`（恒可用）。
- **两个要知道的现状**：
  - GUI 恒传 `--output`（ui/gui/main.go:1805-1809）。按 CLI 的规则「`--output` 显式指定直接解进去」，所以从 GUI 解压是把内容直接解到归档所在目录，**不走** CLI 缺省的智能解压（单根直落、散装包另起一层）。
  - GUI 不传 `--force`，所以同名文件一律跳过；任务摘要会如实写「跳过 N」或「没有新文件（已存在的 N 项已跳过）」（`extractSummary`，ui/gui/service.go:647-669）。
- **GUI 没暴露的解压旗标**：`--force`、`--jobs`、`--temp-dir`、`--password-table`、`--comment`、`--comment-file`、`--quiet`。

### 2.6 刻录光盘

`pageBurn`，ui/gui/main.go:5575-5861。

- **输入**：任意数量的文件 / 文件夹，三种加入方式——整页拖放（全量加入）、「浏览选择…」（多选文件，含 `.iso`）、「选择文件夹…」（单选目录）。去重保序，清单卡与压缩台同款（可拖拽排序、悬停出移除徽章），右侧有「清空」。镜像与其它内容混排 GUI 不拦，交给引擎拒绝。
- **刻录机**：进页时枚举一次 `zpack burn devices`，之后只有点「刷新」才会重新枚举。下拉项格式 `序号 · 厂商 型号（介质状态）`（`burnDeviceLabel`，ui/gui/main.go:5478-5480），缺省选第一台。行副标：枚举失败时 `设备枚举失败`；没有设备（含枚举尚未返回时）`未检测到刻录机`；有设备 `共 N 台`。没有设备时不出下拉，只出「刷新」。

| 行 | 可调内容 | 对应旗标 |
|---|---|---|
| 光盘名称 | 见下方规则表；可改名时是输入框，否则是一句说明 | `--volid <名称>`（可改名且非空才传） |
| 写入模式 | 可追加（缺省）/ 一次性烧录 | `--mode multi` / `--mode mastered` |
| 刻录速度 | 滑杆七档：自动（缺省）/ 4x / 8x / 16x / 24x / 32x / 48x | 自动不传；其余 `--speed 4/8/16/24/32/48` |
| 先擦空再烧 | 开关；**只在所选设备的介质名含 `RW` 或 `RE`、且不是 `DVD+RW` 时出现** | `--blank` |
| 写入提醒（条件出现，见规则四） | 只有一句说明，不可调 | — |

- **写入模式下方的提示**随选项与平台变（ui/gui/main.go:5724-5734）：可追加在 Windows 上是「不封盘，之后还能继续追加；Windows 后续将支持真 UDF 优盘式（可删改）」，在 macOS / Linux 上是「不封盘，之后还能继续追加；已写入的内容不能删」；一次性烧录是「封盘定稿，这张盘之后不能再写；老 DVD 机 / 车机兼容最好」。
- **主行动**：`[清除]`（清空刻录内容）`[刻录]`。主按钮不可点时按钮上直接写原因：

| 条件（按先后） | 主按钮文字 |
|---|---|
| 刻录内容为空 | 先放入刻录内容 |
| 没有刻录机 | 未检测到刻录机 |
| 所选设备被 `burnBlockReason` 拦下 | 拦截原因（见下表） |
| 其余 | 刻录 |

**介质状态规则一：设备下拉的括注** `burnMediaSuffix`（ui/gui/burnstate.go:40-62）。只给明确认识的状态加括注，认不出的不加。

| status | 括注 |
|---|---|
| `blank` | （空白） |
| `appendable` | （可追加） |
| `full` | （已满） |
| `no-media` | （无介质） |
| `damaged` | （状态异常） |
| `erase-required` | （需先擦除） |
| `write-protected` | （写保护） |
| `unsupported` | （不支持） |
| `unrecognized` | （认不出） |
| 其它（空串、`unknown`、Linux 原样短语…） | 不加 |

**介质状态规则二：光盘名称行** `planBurnVolumeName`（ui/gui/burnname.go:30-57）。只有空白盘（或计划先擦空）能起名——名称属于最后一个区段，已有内容的盘沿用盘上名称。

| status | 能否改名 | 标签副标 | 控件位置上是什么 |
|---|---|---|---|
| `blank`，或任何状态但勾了「先擦空再烧」 | 能 | 仅空白盘可设 | 输入框。占位：刻录内容恰好是一个文件夹时「留空用文件夹名」，否则「留空用默认名」。非 Windows 平台下方多一句「macOS/Linux 下只保留字母、数字和下划线」 |
| `appendable` | 不能 | 沿用盘上名称 | 这张盘已有内容，名称保持不变 |
| `full` | 不能 | 已封盘 | 这张盘已封盘，不能再写入 |
| `no-media` | 不能 | 需空白光盘 | 放入空白光盘后可以设置名称 |
| 没选设备（status 为空） | 不能 | 需空白光盘 | 放入空白光盘后可以设置名称 |
| `damaged` | 不能 | 此盘无法写入 | 这张盘上一个区段没有正常关闭，无法写入 |
| `erase-required` | 不能 | 需先擦除 | 打开「先擦空再烧」后可以设置名称 |
| `write-protected` | 不能 | 写保护 | 这张盘处于写保护状态，无法写入 |
| `unsupported` | 不能 | 不支持该盘 | 当前刻录机不支持这张光盘 |
| `unrecognized` | 不能 | 认不出此盘 | 光驱读不出这张光盘，请检查是否放反或卡牢。引擎的 `note` 里带了排查提示时，换成「光驱读不出这张光盘。」+ 引擎那句（更全：放反 / 没卡牢 / 盘型超出光驱能力 / 划伤或太脏） |
| 其它认不出的 | 不能 | 需空白光盘 | 放入空白光盘后可以设置名称 |

能改名时输入值去首尾空白后非空才传 `--volid`，空着不传、交给引擎缺省（单个目录 = 目录名）。不可改名时不摆灰掉的输入框，直接用一句话说明原因。

**介质状态规则三：主按钮拦截** `burnBlockReason`（ui/gui/burnstate.go:11-37）。只拦明确认识的状态。

| status | 没勾「先擦空再烧」 | 勾了「先擦空再烧」 |
|---|---|---|
| `full` | 光盘已封盘 | 光盘已封盘 |
| `no-media` | 未放入光盘 | 未放入光盘 |
| `damaged` | 光盘状态异常 | 放行 |
| `erase-required` | 光盘需先擦除 | 放行 |
| `write-protected` | 光盘被写保护 | 光盘被写保护 |
| `unsupported` | 不支持这张光盘 | 不支持这张光盘 |
| `unrecognized` | 光驱认不出这张光盘 | 光驱认不出这张光盘 |
| `blank`、`appendable`、空串、`unknown`、其它 | 放行 | 放行 |

「不拦认不出的状态」是有意的：macOS 有盘时引擎报的 status 是空串，Linux 可能是 xorriso 的原样短语，按状态拦就会误拦这两个平台（ui/gui/burnstate.go:3-7）。`unrecognized` 不属于「认不出」——它是 Windows 引擎明确报出的「光驱认不出这张盘」，所以要拦，勾了「先擦空再烧」也不放行（盘的身份都读不出，擦除无从谈起）。

**介质状态规则四：写入提醒行** `burnImageCaution`（ui/gui/burnstate.go）。刻录内容恰好是一个镜像（`.iso` / `.img` / `.bin`，只认扩展名）、所选设备的状态是 `appendable`、且没勾「先擦空再烧」时，在主按钮上方多出一行「写入提醒 / 镜像不合并」。**只提醒、不拦截**——主按钮照常是「刻录」（2026-11-24 用户拍板：警告后允许）。

| 条件 | 出不出这一行 |
|---|---|
| 镜像 + `appendable` | 出。控件位置上写：这张盘已有内容。镜像是原样写进新区段的，不会与原有文件合并——写入后通常只看得到镜像里的文件，原有文件虽没被擦掉，但一般工具读不到。要追加到原有文件之后，请改用文件夹或文件；要保留原有文件，请换一张空白盘 |
| 镜像 + `blank` | 不出（空白盘上没有「原有文件」） |
| 镜像 + `appendable` + 勾了「先擦空再烧」 | 不出（擦完就是空白盘） |
| 文件夹 / 多项内容 + `appendable` | 不出（引擎会导入上一区段，原有文件保持可见） |
| 镜像 + 空串（macOS 有盘时） | 不出——判不出盘上有没有数据，宁可不说 |

引擎在 stderr 里也打同一条警告（burn.md 3.4 的 `[WARN]`），但 GUI 不显示过程日志，刻录又不可逆，所以提醒要在点下去之前看到。Linux 上状态同样是 `appendable`，这一行同样生效。

- **刻录任务**没有产物文件：任务卡不出「显示」钮，摘要与失败文案按「刻录」组句（ui/gui/service.go:1034-1045）。
- **GUI 没暴露的刻录旗标**：`--close`、`--no-eject`、`--mode live`。

### 2.7 归档浏览

`pageArchive`，ui/gui/main.go:4432-4638。

- **输入**：整页拖放取首件，或「浏览选择…」单选。
- **归档卡** + **体检行**（`zpack list`，`ListArchive`）：读取时「读取中…」；成功 `大写格式 · N 个文件 · 解压后 <体积> · 归档 <体积>`，加密再加 `· 已加密`；失败红字 `<引擎 error_info> · 仍可尝试校验`。换归档后过期结果丢弃。
- **内容清单**：卡片里逐行列出条目名与体积，**最多显示 500 条**，超出时末尾写「…仅显示前 500 条，共 N 条」（ui/gui/main.go:4543-4569）。所有条目都用文件图标，目录条目不另标。
- **校验归档**（`zpack test`，`TestArchive`）：校验中显示「校验中…」；通过显示绿色「全部通过 · N 条目」；失败显示「N 处损坏」并列出前 3 条明细，其余汇总成「…另有 N 条损坏明细」（ui/gui/main.go:4499-4531、4612-4638）。
- 没有解压入口、密码框、过滤、目录树、预览——DESIGN.md §1.3 里画的这些都没实现。`list` 不带 `--password`，加密归档在这里只会显示引擎的报错。

4. 输出位置（`convertOutRow`，ui/gui/main.go:4691-4724）：可输入、可点「选择」；留空 = 源文件旁。

补充说明：

- **图片压缩的四种策略**（ui/gui/main.go:3299-3348）：先缩尺寸 `size-first`（清晰度钉视觉无损档，逐档缩小，到极限再降画质兜底）/ 只缩尺寸 `size-only`（画质不动，缩到极限仍装不下则失败）/ 先降画质 `quality-first`（分辨率不动，逐档降清晰度，不够再缩尺寸）/ 只降画质 `quality-only`（分辨率绝不缩小）。
- **图片压缩的质量边界提示**：清单里有非 JPG 时出一条浅黄警告——全是无损格式时说明「目标体积压缩只支持 JPG，可先在『图片转换』转成 .jpg」；部分是 JPG 时说明「目标体积对它们不生效——逐张任务会报错，其余照常压缩」。是否 JPG 按扩展名判断（ui/gui/main.go:3291-3365）。多张图是**逐张起任务**，一批任务一起进处理台。
- **图片预览画框**：图片转换页，以及图片压缩页只有一张图时，输入字段正上方有 4:3 的画框（Contain 保比例，图再大也不出框）；输入字段副标显示像素尺寸 `W × H px`；点击画框 = 在文件管理器中显示。解码异步，期间显示「读取中…」，解不了显示文件图标占位（ui/gui/main.go:2703-2773）。
- **Office 的目标格式**只读，按源扩展名定：`.doc` / `.wps` → `.docx`，`.xls` / `.et` → `.xlsx`，`.ppt` / `.dps` → `.pptx`；其它扩展名显示「待选择 DOC/XLS/PPT（或 WPS 家族）」且主按钮置灰（`officeTargetOf`，ui/gui/main.go:3552-3562）。
- **PDF 合并**的清单顺序就是合并顺序，可拖拽排序。
- **新建图片**的输出位置缺省是桌面（`~/Desktop`）；尺寸支持三种写法：`800x600` 像素、`55x90mm|cm|in`（配打印密度，缺省 300）、纸型 `a4` / `a4l` / `letter` 等。
- 各页都没有暴露的常用旗标：`--preset`、`--screen`、`--codec`、`--quality`、`--libreoffice-path`、`--quiet` 等，完整清单见各自的 spec。

|---|---|---|---|---|
| 生成密钥 | 无文件输入 | 密钥长度 `1024` / `2048` / `4096`（缺省 2048）；名字（缺省 `keypair`）；保存位置（缺省桌面，只读展示 + 选择钮） | 恒可用 | 结果卡：「已生成 N 位密钥对」+ 私钥行 / 公钥行（点文件名 = 复制全路径，各带「在 Finder 中显示」钮）+ 保存位置行（点击复制）；失败显示红字原因 |
| 加密 | 文本态：明文文本域 + 公钥字段；文件态：输入文件 + 输出文件（缺省 `<输入>.enc`）+ 公钥 | 输入方式 文本 / 文件（缺省文本） | 公钥已选，且明文非空或文件已选 | 文本态：只读的密文 Base64 + 复制钮；文件态：产物路径 · 体积 + 定位钮；失败红字 |
| 解密 | 文本态：密文 Base64 + 私钥；文件态：密文文件 + 输出文件（缺省 去掉 `.enc` 再加 `.dec`）+ 私钥 | 输入方式 | 私钥已选，且密文非空或文件已选 | 文本态：明文 + 复制钮；文件态同上 |
| Base64 | 单输入框（3–8 行）；状态行「已输入 N」+「清除」 | 无 | 输入非空 | 两个并排按钮；成功后输入清空，结果作为历史卡插到最前（头行 = 序号 + Encode / Decode 徽标 + 原文 / 结果字数 + 删除钮；点原文行或结果行 = 复制）；失败红字 |
| 文件哈希 | 文件清单（文件夹被忽略并 toast「已忽略 N 个文件夹——哈希只对文件计算」；去重；不排序；「清空」） | 算法 `md5` / `sha1` / `sha256` / `sha384` / `sha512` / `crc32`（缺省 sha256）；期望值（仅清单恰好 1 项时出现，可选） | 清单非空且期望值合法 | 每个文件一张结果卡：完整路径 + 算法徽标 +（校验时）「匹配 / 不匹配」+「复制」钮 + 哈希全文；失败红字 |
| 随机生成 | 无 | 段选 密码 / UUID。密码：长度 `8` / `12` / `16` / `24` / `32` / `64`（缺省 16）+ 字符集多选；UUID：格式 标准 / 大写 / 无连字符 / 大写无连字符（缺省标准） | 密码模式下至少勾一类字符 | 等宽字体的结果卡 + 复制钮；失败红字 |

- **加密 / 解密的文件与钥匙字段各自是拖放区**：拖到哪个字段就填哪个。换输入文件后，输出文件位置如果没被用户改过，会跟着清空重算（ui/gui/main.go:2180-2186）。
- **生成密钥的 GUI 侧覆盖守卫**：起命令之前先查 `<保存位置>/<名字>_private.pem` 与 `_public.pem`，任一已存在就直接显示红字「密钥文件已存在: <路径>」，不发命令（ui/gui/main.go:2515-2523）。引擎侧也有同样的守卫，这里是双保险。
- **随机生成的字符集下拉**（`pwCharsetSelect`，ui/gui/main.go:4236-4299）：四个内置类（小写 `a–z`、大写 `A–Z`、数字 `0–9`、符号），缺省全开；分隔线下「自定义 ▸」子菜单分五组符号——标点 `.,:;!?`、括号 `()[]{}<>`、运算 `` +-=*/\^_|~ ``、引号 `` '"` ``、货币等 `$#@%&`——五组恰好铺满 32 个 ASCII 符号。勾选不关菜单。触发器显示已选摘要（如 `小写·大写·数字·符号`、`自定义`），全不选显示「未选择」且主按钮置灰。
- 这六个页面的结果都显示在页面内，**不进处理台**；运行期间主按钮置灰。加密 / 解密 / 生成密钥三页在按钮旁显示「处理中…」，另外三页没有这个提示，只靠主按钮置灰。

## 3. GUI 如何调用引擎

GUI 是薄壳：所有数据都经 `zpack` 二进制的 stdout JSON 契约，引擎层不知道 GUI 的存在（ui/doc.go:11-14、ui/gui/DESIGN.md:4）。这一节写清楚引擎二进制怎么找、调了哪些命令、读了哪些字段、任务状态怎么来。输出契约本身（信封、退出码、stderr 格式）以 [conventions.md](conventions.md) 为准。

### 3.1 架构

- `ui/gui` 是**独立的 Go module**（ui/gui/go.mod:1），不属于仓库主 module；主 module 的 `go build ./...` / `go test ./...` 不会碰它，仓库里也没有 `go.work`。它依赖的只有 mygo 及其间接依赖，**没有一行 import 指向 `core` / `image` / `pdf` / `media` 等引擎包**。
- GUI 与引擎之间只有 `ui/gui/service.go` 一个通道：`exec.Command(<引擎路径>, 参数...)` + 解析（ui/gui/service.go:1-2）。一个任务 = 一个子进程；GUI 不做进程池，也不限并发。
- 参数经 argv 直传，不拼 shell 字符串，所以带空格、中文的路径没问题。代价是 `--password` 也走 argv（CLI 契约如此），压缩 / 解压进行期间密码在系统进程列表里看得到。
- 进程隔离带来的好处：引擎崩溃不会带倒 GUI；引擎可以单独替换（`refresh-engine.sh` 换文件重签即可）；壳技术可换。

### 3.2 引擎二进制的查找顺序

`Service.zpackPath`，ui/gui/service.go:200-227。按顺序取**第一个**通过检查的候选：

| 顺序 | 候选 | 用途 |
|---|---|---|
| 1 | 环境变量 `ZPACK_BIN` | 显式指定；无头测试用它指向一个替身文件 |
| 2 | GUI 可执行文件**同目录**的 `zpack`（Windows 是 `zpack.exe`） | 开发态平铺布局 |
| 3 | GUI 可执行文件**上两级**目录下的 `Resources/zpack(.exe)` | 打包态：`<App>.app/Contents/MacOS/<可执行文件>` → `<App>.app/Contents/Resources/zpack` |
| 4 | 从 GUI 可执行文件所在目录起**向上最多 5 层**，各层的 `bin/zpack(.exe)` | 开发态：仓库产线产物 |
| 5 | `/Applications/zpack Finder Menu.app/Contents/Resources/zpack` | 装机兜底：FinderSync 宿主里内嵌的引擎（路径写死，不带 `.exe`） |

规则：

- 整个进程只解析一次（`sync.Once`），之后不变。
- 每个候选要过三关（ui/gui/service.go:216-224）：非空；**不等于 GUI 自己的可执行文件路径**；可执行——文件存在且不是目录，非 Windows 平台还要有执行位（Windows 没有执行位语义，存在即可，ui/gui/service.go:264-273）。`ZPACK_BIN` 也受这三关约束。
- 「不等于自己」是自体防护：打包态的 GUI 可执行文件名恰好也是 `zpack`，同目录候选会返回它自己，不挡住就会把自己当引擎再 exec，引擎命令变成再开一个 GUI 窗口（ui/gui/service.go:217-219）。
- 第 4 项必须排在第 5 项之前：装机位的引擎可能比仓库里的旧，开发版 GUI 拿旧引擎跑过一次静默覆盖桌面密钥的事故（ui/gui/service.go:211-213）。
- 全部落空 → 空串，即「未找到引擎」：任务类调用返回 nil，界面 toast「未找到 zpack 引擎——请到「设置」查看引擎位置」（ui/gui/main.go:4960-4964）；短命令回调拿到「未找到 zpack 引擎」；设置页引擎路径行显示红字提示。

两个由代码直接推出来、需要知道的后果：

- **Windows 上第 2 项永远命不中**。Windows 的 GUI 产物名就是 `zpack.exe`（`ui/gui/build/windows-amd64/zpack.exe`），与引擎同名，同目录候选恒等于自己、被自体防护跳过。所以在 Windows 上引擎只能靠 `ZPACK_BIN` 或仓库的 `bin/zpack.exe` 找到。而 Windows 安装器（mygo 自带的 NSIS 安装器，按用户装到 `%LocalAppData%\Programs\zpack\`）里只有 GUI 自己和 `resources/` 的副本，不含引擎。合起来的结果：**用安装器装到仓库之外后，GUI 找不到引擎**，除非设 `ZPACK_BIN`。仓库里没有 Windows 侧的引擎注入或安装脚本（`install.sh` 只有 mac 版）。【待确认】是否有仓库之外的做法在用（比如手工拷引擎、改 GUI 可执行文件名）。
- **`go test` 里引擎恒为「未找到」**。测试程序在系统临时目录，向上 5 层碰不到仓库的 `bin`；所以依赖真实引擎的三个用例靠 `repoEngine()` 直接拼 `../../bin/zpack(.exe)`（ui/gui/service_test.go:194-207），其余用例用 `ZPACK_BIN` 指向一个替身文件。

- 解压的 `--output` 恒传（见 2.5）。
- 刻录的参数由纯函数 `burnArguments` 拼（ui/gui/service.go:1048-1063）：`--device` 恒传；速度「自动」不传 `--speed`；名称可改名且非空才传 `--volid`；`--mode` 恒传；`--blank` 勾了才传。
- 期望哈希转小写后再传 `--expect`（ui/gui/main.go:3956-3958）。
- 字符集参数（`pwPasswordArgs`，ui/gui/main.go:4173-4184）：引擎缺省四个内置类全开，所以 GUI 把**没勾**的内置类显式关掉（`--lower false` 这样），自定义分组按分组顺序去重合成一个 `--charset`。

### 3.4 消费的 JSON 字段

GUI 只认下表这些字段。**字段改名或删除都是对 GUI 的破坏性变更**，改之前先看这里。

| 来源 | 读取的字段 | 用途 |
|---|---|---|
| `compress` | `data.archive`；`data.file_count`、`data.size_bytes` | 产物路径（分卷时是 `.001` 那一卷，以此为准）；摘要「N 个文件 · 体积」 |
| `extract` | `data.output`；`data.file_count`、`data.size_bytes`、`data.skipped` | 产物目录；摘要 |
| 转换族（media / audio / image / office / pdf） | `data.output`；`data.size_bytes` 或 `data.output_size_bytes` | 产物路径；摘要「已输出 <文件名> · 体积」。两个体积字段都没有时 GUI 自己去 Stat 产物；`data.output` 为空则摘要回落成「<动作>完成」。刻录任务也走这条管线，但没有产物，不读任何 `data` 字段 |
| `burn devices` | `data.devices[]` 的 `index`、`path`、`vendor`、`product`、`media`、`status` | 刻录机下拉；`status` 喂给三条介质规则；`media` 决定是否出「先擦空再烧」 |
| `info` | `data.format`、`data.file_count`、`data.total_uncompressed`、`data.archive_size`、`data.encrypted` | 解压台体检行 |
| `list` | `data.format`、`data.entry_count`、`data.total_uncompressed`、`data.archive_size`、`data.encrypted`、`data.entries[]` 的 `name` 与 `size` | 归档浏览 |
| `test` | `data.tested_entries`、`data.all_ok`、`data.failures[]` | 校验结果 |
| `crypto encrypt` / `decrypt`（文件态） | `data.output`、`data.size_bytes` | 结果行 |
| `crypto genkey` | `data.private_key`、`data.public_key` | 结果卡的两把钥匙（`--output` 形态下这两个字段是文件路径） |
| `hash` | `data.files[]` 的 `path`、`size_bytes`、`hash`；`data.is_match` | 结果卡；`--expect` 不匹配时信封是 `is_success:false` + `data`，GUI 照常读出结果并显示「不匹配」 |
| 任何失败 | `error_info` | 见 3.7 |
| 纯文本命令（`crypto password` / `uuid`、`base64`、文本态 `crypto encrypt` / `decrypt`、`--version`） | stdout 全文，去掉末尾换行 | 文本结果；失败时 stdout 上是 `{"error_info":…}`，按失败信封解析 |

另外两处 GUI 对引擎输出有隐含依赖，改引擎时要留意：

- 解压台与归档浏览的 toast 靠**子串匹配** `error_info`：含「无法识别」就显示「格式不支持：<文件名>」，否则原样点名（`toastEngineVerdict`，ui/gui/sniff.go:149-159）。引擎改这句文案，这里要跟着改。
- 刻录的三条规则靠 `burn devices` 的 `status` **字符串取值**（`blank` / `appendable` / `full` / `no-media` / `damaged` / `erase-required` / `write-protected` / `unsupported`）。取值表变了，规则表要同步。

### 3.5 任务：进度、状态与取消

任务管线只用于进处理台的四类调用（压缩、解压、转换、刻录），核心是 `runTask`（ui/gui/service.go:336-404）。

- **进程**：`exec.Command` 起 `zpack`，stdout 与 stderr 各接一根管道。stderr 由另一个 goroutine 逐行读、找进度行；stdout 整段读完；最后 `Wait` 取退出码。
- **状态**：`Task.State` 四态——运行中 / 完成 / 失败 / 已取消（ui/gui/service.go:44-50）。引擎 goroutine 写、界面帧读，所以界面只读 `View()` 返回的快照（ui/gui/service.go:53-70）。
- **重绘**：每次进度更新往 `Updates` 通道发一个信号（缓冲 8，满了就丢——下一帧总会重绘）；任务收尾时关闭通道。`watchTask` 靠通道关闭退出，所以**收尾必须关通道**，否则失败提示与完成后策略永远不执行，每个任务还漏一个 goroutine（ui/gui/service.go:121-143）。
- **终态判定**：退出码 0 → 完成（百分比置 100）；非 0 → 失败，原因取 `error_info`，取不到用「<动作>失败（exit N）」；进程起不来 → 失败，「启动引擎失败：<原因>」。已取消的任务再收到收尾信号时保持取消态（ui/gui/service.go:124-143）。
- **进度行解析** `parseProgressLine`（ui/gui/service.go:434-451）：去掉 `[时间]` 前缀后，正文必须同时含「中」和一个 `N%`；取第一个百分比，把它之后用 ` | ` 分隔的明细改成用 ` · ` 连接。

  样例：

  ```
  [2026-11-21 12:00:00] 压缩中 █████░░ 25.0% | 500.0MB/2.0GB | 100.0MB/s | 1/4 文件 | 剩余 15秒
  ```

  解析出 25.0，明细 `500.0MB/2.0GB · 100.0MB/s · 1/4 文件 · 剩余 15秒`。

- **哪些任务有进度**：只有会打这种行的任务才有——压缩包引擎的压缩与解压（5 秒采样一次）。以下都不会动进度条，任务卡停在「启动中…」+ 0% 直到结束：7z 压缩（引擎打的是「压缩中 已写 …」，没有百分比）、刻录（心跳「刻录中… 已用 N 秒」）、没有总量的解压（引擎退化为计数模式，没有百分比）、媒体 / 图片 / PDF / Office 转换（不打进度行）。
- **取消** `Task.Cancel`（ui/gui/service.go:147-167）：把子进程杀掉，然后清半成品。杀进程的动作会**等子进程真正退出**才返回（`runTask` 里 `cmd.Wait` 返回后关闭 `exited`，上限 `KILL_WAIT_TIMEOUT` 5 秒，ui/gui/service.go:336-404）——Windows 上 `Kill` 返回时进程可能还没退、仍握着输出文件，不等就删会撞上「文件被占用」（6.6）。**只有压缩任务登记了清理动作**（删归档本体与已切出的 `.001/.002…` 分卷，ui/gui/service.go:169-177、300）；其它任务被杀时引擎自己的收尾逻辑不会跑，半成品产物文件可能留下。取消是幂等的；已结束的任务点取消什么都不动。
- **完成后策略**在派发那一刻取快照（`launchTask`，ui/gui/main.go:4960-4971），中途改设置不影响在飞任务；只有成功才打开文件夹，失败 / 取消不打扰（ui/gui/main.go:4991-4995）。
- **失败必有一个可见的出口**：任务失败时无论用户在哪个页面，都弹一条 toast「<任务标题> 失败：<原因>」，原因超过 120 个字符截断（ui/gui/main.go:4983-4990）。

### 3.6 回调与线程约定

Service 层的每个方法都是「立即返回，结果走回调」。下面五条是硬约定：

1. **Service 给页面的回调必须在后台协程里给，不许同步回调。** `Service.BurnDevices` 在「未找到引擎」分支原本是同步回调，页面回调里的 `mygo.RunOnMain` 在无头测试环境下永远等不到主循环，整套 GUI 测试挂死（AGENTS.md:258；现状见 ui/gui/service.go:1003-1008）。其余方法本来就是 `go func(){…}`。
2. **回调里改界面状态，必须投递回主线程**：包在 `mygo.RunOnMain(func(){…})` 或 `a.win.Update(func(){…})` 里。
3. **Toast 只能在建帧期间调 `c.Toast`**。帧外（goroutine、引擎回调）一律 `a.queueToast(消息)` 入队，下一帧开头由 `drainToasts` 倒出来（ui/gui/sniff.go:117-134）。
4. **文件对话框必须在 goroutine 里发起**。在帧构建闭包里同步调 `mygo.Dialog.Open`，会把主 goroutine 卡进嵌套事件泵，帧构建重入后选择面板失灵（ui/gui/main.go:872-874）。
5. **`watchTask` 必须带 `go` 起**——它阻塞到任务收尾，同步调用会冻住建帧（ui/gui/main.go:4959-4970）。

### 3.8 stderr

GUI 不向用户展示引擎的 stderr。它唯一的用途是任务管线里找进度行（3.5）；页内短命令用 `cmd.Output()`，stderr 直接丢弃。因为 GUI 不传 `--quiet`，引擎照常输出「开始执行」与进度行。

## 4. 行为细则

页面的输入、参数与主行动已在第 2 节逐页写明，引擎调用在第 3 节。这一节补跨页面的规则：默认值、同名保护、前端校验、格式守卫、右键菜单的完整流程、边界输入。

### 4.1 正常路径

**GUI 压缩**

1. 拖入文件 / 文件夹，或点「浏览选择…」。清单出现，名字与保存位置自动取首输入。
2. 需要时展开「高级设置」改级别、密码、分卷。
3. 点「创建压缩包」→ GUI 拼出输出路径（同名加序号）→ 界面切到处理台 → 起子进程 `zpack compress …`。
4. 引擎每 5 秒在 stderr 打一行进度，任务卡的进度条与明细跟着走。
5. 结束：退出码 0 → 卡片显示绿色对勾与「N 个文件 · 体积」，出「在 Finder 中显示」钮（指向引擎信封里的 `archive`）；勾了「打开文件夹」则同时打开产物目录。退出码非 0 → 红叉与 `error_info`，另弹 toast。

**GUI 解压**

1. 拖入归档（或 `.001` 首卷）。GUI 立刻起 `zpack info` 体检，同时数分卷。
2. 体检行显示格式、文件数、解压后体积、分卷数、是否加密。
3. 加密归档填密码；不填解压位置就是归档所在目录。
4. 点「解压」→ `zpack extract <归档> --output <目录> [--password …]` → 处理台。
5. 已存在的同名文件被引擎跳过，摘要里写明跳过数量。

**Finder 右键**（macOS）

1. 选中若干项右键。扩展对每个选中的非目录文件跑一次 `zpack list <文件>`，退出码 0 即判为归档；目录一律按非归档算。
2. 出现一级菜单「zpack ▸」（带图标）。选中项含非归档 → 有「压缩为 ZIP」「压缩为 TAR.GZ」；含归档 → 有「解压到此处」「测试归档」；两者都有时中间加分隔线。
3. 点菜单项 → 扩展把 `{verb, paths}` 写进自己沙箱容器里的 `zpack-job.json`，再拉起宿主 app。
4. 宿主启动后每 0.1 秒轮询任务文件，最多 5 秒；读到即删（防重复执行），然后跑内嵌的 `zpack`，弹出进度窗。
5. 结束后窗口切到完成态：标题说动作，正文说产物与位置；有「完成后打开文件夹」「完成后自动关闭」两个对钩（记忆在 UserDefaults）；「确定」按钮带 5 秒倒计时，回车即确认。关窗后宿主退出。
6. 裸启动宿主（双击、误触）5 秒没有任务就自己退出。

### 4.2 默认值与同名保护

各页默认值的唯一定义点是 `newApp`（ui/gui/main.go:5078-5084），测试与真实启动共用：

| 项 | 缺省 |
|---|---|
| 格式 / 级别 / 分卷 / 密码 | `.zip` / 6 / 不分卷 / 无密码 |
| 完成后 | 无动作 |
| 密钥长度 | 2048（段选第二项） |
| 视频格式 / 图片格式 | `.mp4` / `.png` |
| 视频压缩目标 | `50%` |
| 音频格式 | `.mp3` |
| 图片压缩目标 / 策略 | `100KB` / 先缩尺寸 |
| Office 引擎 | 自动 |
| PDF 旋转方向 / 页面尺寸纸型 | 右转 90° / `a4` |
| 哈希算法 | `sha256` |
| 密码长度 / UUID 格式 / 字符集 | 16 / 标准 / 四个内置类全开 |
| 刻录写入模式 | 可追加 |
| 首页 | 压缩台 |

**同名不覆盖**：GUI 拼出来的产物路径（压缩包、各类转换产物、PDF 产物、新建图片、PDF 合并）在起命令前先查一下，已存在就变成 `名字 2.ext`、`名字 3.ext` …直到找到空位（`uniquePath`，ui/gui/service.go:454-467）。这是 GUI 侧的保护；CLI 自己的规则是覆盖。序号试到 9998 仍全占就原样返回（会覆盖）。

**输出位置的缺省**：压缩 = 首输入所在目录；解压 = 归档所在目录；单文件转换 = 源文件旁；图片压缩 = 首图所在目录（多张时全部输出到这里）；PDF 合并 = 首文件旁；新建图片 = 桌面；生成密钥 = 桌面。

**「完成后」策略的作用范围比控件大**：`donePolicy` 是整个 app 的一个字段，派发任何任务时都会读它（`launchTask`，ui/gui/main.go:4970）——在压缩台选了「打开文件夹」之后去转一个视频，转完也会打开文件夹。但这个下拉只出现在压缩台与解压台。刻录任务没有产物目录，不受影响。

### 4.3 前端校验

参数框里的内容由 `ui/gui/validate.go` 的纯函数判定（规则出处 ui/gui/validate.go:58-268）。填错 → 控件下方红字 + 主按钮置灰；必填项**空着只置灰、不飘红**（`visibleIssue`，ui/gui/validate.go:51-56）。

| 输入 | 规则 | 红字文案 |
|---|---|---|
| 页码区间（PDF 提取必填；PDF 旋转 / 页面尺寸可选） | 逗号分隔；每段是正整数、`a-b`、`a-` 或 `-b`；`a` 不大于 `b`；区间两侧不能夹空格 | `页码区间必填，如 1-3,5,8-` / `页码区间里有空段（检查逗号）` / `页码「X」要用正整数` / `页码区间「X」起点大于终点` / `页码「X」看不懂，如 1-3,5,8-` |
| 自定义分卷尺寸 | 正整数 + 可选单位 `B` `K` `KB` `M` `MB` `G` `GB`（不写单位 = 字节），或介质模板名；不低于 64KB | `体积必填，如 100MB、2GB、65536` / `体积要大于 0，如 100MB、2GB、65536` / `不能小于 64KB（分卷下限）` |
| 自定义视频目标 | 百分比 1–100、体积（规则同上、无下限），或介质模板名 | `目标体积必填，如 80MB 或 50%` / `百分比要 1–100，如 50%` / 同体积规则 |
| 自定义图片目标 | 同体积规则、无下限 | 同体积规则 |
| 音频码率（可选） | 数字 + 可选 `k`，1–3200 | `码率要 1–3200 的数字加 k，如 128k` |
| 采样率（可选） | 8000–192000 的整数（只看开头的数字） | `采样率要 8000–192000，如 44100` |
| 新建图片尺寸（必填） | `宽x高`（正数）+ 可选 `mm` `cm` `in`；或纸型 `a0`–`a5` `letter` `ledger`；可带 `L` / `P` 尾缀定方向 | `尺寸必填，如 800x600 / 55x90mm / a4` / `尺寸格式不对：800x600 / 55x90mm / a4` / `宽高要是正数，如 800x600` |
| 新建图片颜色（可选） | 色名、`transparent`、`#RRGGBB` 或 `#RRGGBBAA` | `颜色写色名（red）或 #RRGGBB / #RRGGBBAA` |
| 打印密度（可选） | 1–2400 的整数 | `打印密度要 1–2400 的整数，如 300` |
| 期望哈希（可选） | 十六进制；位数与算法一致（crc32 8 / md5 32 / sha1 40 / sha224 56 / sha256 64 / sha384 96 / sha512 128） | `期望值只能是十六进制字符（0-9、a-f）` / `<算法> 的哈希是 N 位，现在是 M 位` |

校验只管语法与范围。要看文件的事（页码是否超出、文件是否还在）交给引擎。规则是照引擎的解析逐条抄的，铁律是「GUI 判错的，引擎一定也判错」——宁可漏判，不可误拦（ui/gui/validate.go:9-15）。

两个照抄引擎连缺陷一起抄的例子：体积不认 `TB`、不认小数；纸型 `legal` 因为引擎的「尾缀 L = 横向」规则被误伤（`legal` 去掉尾缀 `l` 变成 `lega`），GUI 同样判错（ui/gui/validate_test.go:58、114-117）。

### 4.4 格式守卫：文件头分类

`classifyMagic`（ui/gui/sniff.go:43-95）只读文件前 300 字节：

| 文件头特征 | 判为 |
|---|---|
| `%PDF-` | `pdf` |
| 偏移 4 处是 `ftyp`，且品牌是 `heic` `heix` `hevc` `heim` `heis` `mif1` `msf1` `avif` 之一 | `image` |
| 其它 `ftyp`（mp4 / mov / m4a） | `av` |
| EBML 头 `1A 45 DF A3`（mkv / webm） | `av` |
| `ID3`、MPEG 音频帧同步 `FF Ex`、`fLaC`、`OggS` | `av` |
| `RIFF` 且偏移 8 是 `WAVE` 或 `AVI ` | `av` |
| `RIFF` 且偏移 8 是 `WEBP` | `image` |
| JPEG `FF D8 FF`、PNG、`GIF8`、TIFF（`II*\x00` 或 `MM\x00*`）、OpenEXR `76 2F 31 01`、Radiance `#?RADIANCE`、JPEG XL 裸流 `FF 0A` | `image` |
| OLE2 复合文档 `D0 CF 11 E0 A1 B1 1A E1`（doc / xls / ppt 与 WPS 家族） | `office` |
| `PK\x03\x04`、`PK\x05\x06`、`Rar!`、7z、gzip `1F 8B`、`BZh`、xz `FD 37 7A 58 5A 00`、zstd `28 B5 2F FD`、`MSCF`、偏移 257 处 `ustar` | `archive` |
| 前 64 字节全是可打印字符或空白（含所有 ≥ 0x80 的字节，所以中文文本也算） | `text` |
| 其它，或文件打不开、读不出 | 空串 = 不认识 |

各页要求的族：视频转换 / 视频压缩 / 音频转换 / 音频压缩要 `av`；图片转换要 `image`；图片压缩逐张要 `image`；PDF 提取 / 旋转 / 页面尺寸三页与 PDF 合并逐件要 `pdf`；Office 转换要 `office`。压缩台、刻录清单没有守卫；解压台、归档浏览不设守卫，由引擎 `info` / `list` 的结论说话。

判定只看内容不看扩展名（用户定案，ui/gui/sniff.go:3-6）：改了扩展名的文件按真实内容走；认不出的长尾格式（引擎可能支持）一律放行。

### 4.5 体积写法

全 GUI 只有一个 `humanSize`（ui/gui/service.go:498-519）：整数位不带小数（`3GB`、`5MB`、`1023B`），否则一位小数（`2.3MB`）；数字与单位之间不留空格；先按一位小数取整，取整后进位（1023.96KB → 1MB）。单位到 TB 为止。

### 4.6 边界与退化输入

| 输入 | 现状 |
|---|---|
| 清单删到空 / 选档被移除 | 回到空态 hero。移除在建帧结束后才落地，删最后一项不会崩（ui/gui/main.go:1598-1604） |

| 拖入的文件不属于这一页的族 | toast「格式不支持：<文件名>」，不落位 |

| 往单文件转换页拖**文件夹** | 守卫拦不住（文件夹读不出文件头 = 不认识 = 放行），要到处理台才看到引擎报错（由 ui/gui/sniff.go:20-32 推出，未实测） |

| 归档条目超过 500 条 | 只列前 500 条，末尾注明总数 |
| 密钥文件已存在 | 不发命令，直接红字（GUI 侧守卫） |
| 窗口拉到最窄 | 路径换行不截断；引导句先收缩折行，窄到放不下按钮才把按钮换到下一行 |
| 明文以 `-` 开头（如 Markdown 列表） | 文本一律走 stdin 送给引擎，不会被当成旗标（ui/gui/service.go:952-958） |
| 任务派发后、进程起来前就点取消 | 进程一起来即被补杀（ui/gui/service.go:358-360） |

### 4.7 错误处理

错误怎么呈现见 3.7 的表。这里补两条清理语义：

- **压缩任务**被取消或失败后没有半成品：取消时 GUI 删归档与分卷；引擎自己中途失败也会删。
- **其它任务**（解压、转换、刻录）被取消时只是把进程杀掉，GUI 没有登记清理动作，引擎的收尾也不会跑——可能留下半截的产物文件。已解出的一部分文件、已写入光盘的区段更不会回退。

## 6. 设计与陷阱

**改动这个功能之前必须知道的事。** 这里的条目来自 AGENTS.md 的「GUI 交互铁律」与「FinderSync 陷阱清单」、`ui/doc.go`、`ui/gui/DESIGN.md`、`ui/gui/MYGO-COMPONENTS.md`，以及代码注释里带日期的定案。凡标注「据 AGENTS.md」的是 mac 上的实测记录，写这份 spec 时在 Windows 机器上无法复验。

### 6.1 架构决策

- **为什么是薄壳**：UI 零引擎代码、进程级隔离、壳技术可换；引擎为此净化过（错误一律 error 返回、日志走回调、不碰 stdout），所以将来真要进程内嵌也可以直连 `core` 包——这是留着的后门，现在没用（ui/doc.go:11-14）。DESIGN.md 的说法是「厚 UX、薄引擎」（ui/gui/DESIGN.md:4）。
- **为什么是独立 module**：mygo 及其一串间接依赖不进主 module，CLI 的依赖面不被 UI 框架污染（ui/gui/go.mod）。
- **壳技术的选型过程已经结束**：`ui/doc.go` 与 AGENTS.md:357 还写着「壳技术另议 / 调研完毕待原型验证」，实际早已选定 mygo v0.10.0 并交付（ui/gui/go.mod:5-7）。
- **消费的是契约不是 Go 包**：所以引擎输出字段的任何改名、删除，都是 GUI 的破坏性变更，而且编译期发现不了（[conventions.md](conventions.md) 第 6 节）。3.4 的字段表就是这份依赖清单。
- **同名保护放在 GUI 侧**：CLI 的规则是覆盖，GUI 面向的是拖拽即走的用户，误覆盖不可接受，所以由 GUI 先找空位再调命令。

### 6.2 组件先查再造

教训（2026-11-21，用户震怒，ui/gui/MYGO-COMPONENTS.md:3-5）：清单拖拽排序手搓了 8 轮提交仍然变高行错位，而框架的 `ui.List` + `ListState.Reorder` 开箱即得（换用后退役 217 行手搓代码）。

规矩（ui/gui/MYGO-COMPONENTS.md:58-64）：

1. 任何交互行为动手前先查 `ui/gui/MYGO-COMPONENTS.md` 的组件清单与使用审计。
2. 用了组件但深度定制（比如 `ButtonBase` 自绘）要注明「机件合规」；纯手搓必须先在清单里记一行弃用理由。
3. 组件行为存疑直接读框架的 `examples/`。
4. 新增可点元素必须在 `feedbackTargets` 登记。
5. 页面函数假定清单非空；清单增删在建帧结束后才落地。

几处有意识的取舍（ui/gui/MYGO-COMPONENTS.md:37-56）：

- 侧栏不用框架的 `ui.Sidebar`——它的选中态是灰 pill，违背设计定案，改用自绘 `navItem`。
- mygo v0.10.0 没有独立的多选组件，带主题的菜单选一项就关。随机生成页的字符集多选用 `MenuBase` + `CheckItem` + `KeepOpen` + 子菜单拼出来。
- 框架 `ui.Link` 只有悬停下划线、没有按下态，按下字色自己补。
- 任务卡暂留手写（条数少），多起来再换 `ui.List`；进度显示目前用的是框架 `ui.Progress`。

### 6.3 交互铁律

2026-11-21 用户定案，所有可点元素无例外（AGENTS.md:359-371）。

1. **凡可点击必带悬停特效 + 按下反馈 + 手型光标。** 悬停变色 / 加深 / 放大任一即可，按下要有「被按下去」的感觉（下沉 / 缩放 / 变色任一）。静止态可以隐藏（比如行悬停才浮现的操作钮），但浮现后同样要完整反馈。无声无息的可点元素 = bug。唯一例外是实心彩色控件（如红底徽章）：底色反馈会被本体吞掉，用「显著放大」代偿。
2. **符号一律 SVG。** 减号、叉、对勾、箭头都走 `icon()` 管线（16×16 描边），禁止拿特殊 Unicode 字形当图标——"✕" 曾因字体缺字渲染成空方块，用户以为删除功能不存在。任务状态的 ✓ / ✗ 字形同样已换成 `iconCheck` / `iconCross`。
3. **两条图标管线不能混。** `icon()` 生成描边图标，配 `ui.Icon` + `TextColor` 染色；`iconRaw()` 是自带填充色的固定色图标，必须配 `ui.Image`——把它喂给 `ui.Icon` 会把固定色烧成黑色（哈希页、归档清单行的文件图标踩过两次，2026-11-22）。判别法：看定义处走的是哪个函数（ui/gui/main.go:203-211）。
4. **样式覆盖后自查反馈连带。** 剥掉组件自带的底色或边框（比如把下拉融进连体字段）会把悬停底色一起盖掉——覆盖之后必须逐帧回填悬停 / 按下反馈，并补 `Cursor(ui.CursorPointer)`。同理，`ui.PrimaryButton` 自带的悬停 / 按下换脸，一覆盖 `Background` 就没了，所以 `primaryCTA` 只在置灰态才覆盖（ui/gui/main.go:2050-2058）。
5. **反馈语汇只有一处定义**：`pressFeedback`（悬停 `SurfaceHover`、按下再深 8%）、`leadBrowseButton`、`pickButton`、`copyButton`。页面代码不得再内联 `if X.Pressed() || X.Hovered()`。
6. **文件名 / 路径一律完整显示**——不截断、不在中间变色，放不下就换行。被否的两版：单行省略 + 悬停提示；目录段从头省略 + 文件名另色（被判过度设计）。字段行用 `MinWidth(FIELD_MIN_WIDTH)` 钉在控件列内，尾部的「选择」钮 `Shrink(0)` 钉宽，长英文目录名挤不走它。
7. **副标一律一行。** 设置行左列 84px，副标 12px 字一行放七个汉字，超了折行、八个字会掉一个孤字——所以改文案不改布局。
8. **主行动行全页面统一**：只用 `ctaRow`（上距 24、钮间距 10）/ `primaryCTA`（框架 `ui.PrimaryButton`，钮高 44）/ `cancelButton`（描边灰字，悬停泛红、按下更红）。此前各页高度不一（哈希 40、刻录 32、随机与 Base64 40）。
9. **引导行放不下才换行**：`Row.Wrap()` + 句子 `Basis(下限).Grow(1)`——句子先收缩折行，窄到连下限都放不下才把按钮换到下一行。不这么做，最小窗口里这句会被挤成 26px 宽 9 行的竖条。代价是用户选定的：窗口拉宽后按钮靠到右边。
10. **页面函数假定清单非空**（空态由 `pane` 走 hero）。直接渲染空清单会读 `inputs[0]` 越界。**清单增删在建帧结束后才落地**：压缩台与 PDF 合并的参数区在同一帧后面还要读首输入，先删后读，删最后一项即崩（2026-11-23 无头实测复现）。
11. **数值 / 规格输入必须有前端校验**（4.3）。铁律：GUI 判错的引擎一定也判错——宁可漏判，不可误拦。
12. **体积写法**全局一个 `humanSize`（4.5）；体积标签字号 12（次要信息）；字段尾部的「选择」钮一律 `pickButton`，自带 4px 右内缩，悬停色块不贴字段描边。
13. **光标链断点**：mygo 找光标是沿悬停链从内向外找第一个设了 cursor 的节点，途中遇到「可点但没设 cursor」的节点就直接停。官方的 Radio / Checkbox / Switch / Select 触发器都是可点但不设 cursor，放在 `ButtonBase` 里会把外层的手型挡成箭头。整框统一手型的正解是给这些组件的返回值链式补 `.Cursor(ui.CursorPointer)`（压缩策略单选行实证过：圆点区箭头、字区小手的割裂感即此因）。
14. **多行控件行的标签对齐用头渲实测，不猜。** `openSettingRowTop` 里标签列与控件区第一行字天然差一个「控件框上内边距」，修法是标签列补同值的 `Padding(5, 0, 0, 0)`；`AlignItems(ui.Baseline)` 对没有直系文字的控件框解析不稳（实测偏下 3.5px），弃用（ui/gui/main.go:1858-1867）。
15. **mygo 细节**：`Cursor(ui.CursorPointer)` 不会随 `ButtonBase` 自动给，必须手动；动画用 `Animate(key, 目标, 时长)`，逐帧条件调用即可，系统开了「减少动态效果」框架自动直跳。

### 6.4 视觉定案

都来自带日期的用户裁定（ui/gui/DESIGN.md、ui/gui/main.go 注释）：

- **侧栏**：DeepSeek harness 式布局，整条稍深色不透明；选中态是深蓝胶囊 + 白字白图标（覆盖了先前的浅色胶囊方案）；品牌 Z 19px。导航列外套滚动，页多了会超高；**处理台钉在底角**，固定按钮上方必须留 6px——不留的话滚动区下沿那半截行会紧贴到固定按钮顶上。设置随列表滚动、不归分组（2026-11-23 用户定案：与处理台对调，只有处理台固定）。
- **没有独立 Header**：内容从窗口顶直接流下，右半边只有一条页面标题条。Windows 上标题条与标题按钮带严格同高（用户定案：`+8` / `+16` 的呼吸高度都被否，ui/gui/main.go:714-716）。
- **编辑式排版**：左右留白 28（原 56，太空，减半）。
- **品牌水印常驻**：右下 230px、不透明度 0.06，所有页面都显示（初版仅空态显示；第二版 300px / 0.07 被判过重）。水印必须 `IgnoreInput`——它参与指针命中时会遮挡重叠处的可点控件，Z 挪到 `.zip` 格式下拉上时点击被吞（ui/gui/main.go:702-705）。
- **文字色**：正文不用纯黑（浅 `#3f3f46` / 深 `#e4e4e7`）；辅助文字用同一基色调的 60% 不透明度，模仿 macOS 的 secondaryLabel，比正文明显浅一档。颜色 token 的唯一定义点是 `colText*`，页面代码只许用 `t.Text` / `t.TextMuted`（ui/gui/main.go:58-67）。
- **清单移除钮是减号**（语义 = 移出清单，不是删除文件），零空间占用：叠在尺寸槽上层，行悬停时尺寸淡出、减号滑入。
- **压缩台参数区的顺序**（用户定案）：保存位置 → 新压缩包名字 + 后缀 → 完成后 → 高级设置。压缩级别曾被撤出主区，后来按用户要求收进高级区。**高级设置默认折叠**，折叠态只有灰描边、没有白底；头行不解释内容，但有生效项时提示「已启用 N 项」，防止藏着生效的加密 / 分卷。
- **自绘滑杆**（压缩级别、刻录速度）：观感对齐 macOS 原生滑杆——轨道 6pt 胶囊、滑块头 20×16 圆角矩形、按住放大 12% 并出投影。
- **目录体积**：最初定案「不递归求和」（怕拖巨树卡界面），后来改为后台异步求和（用户定案：锦上添花，不卡界面不卡进度）。
- **引擎状态脚注已移除**（「什么引擎？」指向不明，无信息价值）。
- **归档浏览入口保留在侧栏**（用户定案：CLI 的真实能力不轻易撤）。
- **引导行按钮文案与空态 hero 的按钮一致**，都是「浏览选择…」。

### 6.5 主题、字体与清晰度

**主题**

- `brandTheme` 每帧在系统浅 / 深主题上派生品牌色：强调色 = 品牌蓝三态（浅 `#376DB5` / 深 `#5B9BD5`），表面冷调偏蓝，圆角 8（ui/gui/main.go:162-200）。
- **外观三态**（2026-11-22 用户定案「外观必须可调，不止跟随系统」）：跟随系统 / 浅色 / 深色。切换即调 `mygo.Theme.SetSource` 并落盘。启动顺序：`loadThemeMode()` 在窗口创建前读回 → `WhenReady` 里先 `SetSource` 再建窗口；文件缺失、损坏、越界一律回退跟随系统（ui/gui/appearance.go:48-64、ui/gui/main.go:5102、5115）。主题的重建框架自理，不需要手动失效。
- 设置页的外观控件是自绘段选 `toolSegmented`（`TabsBase` 范式：浅灰轨道 + 选中项强调色胶囊），不是框架的 `ui.Segmented`。

**字体的三步演进**（每一步都是对上一步问题的修正）：

1. 2026-11-22 起三平台内嵌 MiSans，经 `ui.RegisterFont` 注册、`brandTheme` 把 `ui.Theme.Font` 指向它，一处生效。选这条路的理由：mygo 的主题字体是 context root family，`SetUIFamily` 在 pango 上是死路。当时注册的是完整可变字体，看中的是 500 / 600 中间字重是真实例。
2. 字重阶梯陷阱：MiSans VF 的字重轴是 150–700、默认 330 的非标准阶梯（Regular 330 / Medium 380 / Demibold 450 / Semibold 520 / Bold 630 / Heavy 700）。Windows dwrite 按最近邻取实例，默认请求的 400 命中 Medium 380，视觉偏细。当时的解法是动字体元数据：把 Medium 实例坐标从 380 改到 450（只改一处元数据，字形不动；轴默认值绝不可动，否则腐蚀变体数据）。
3. 2026-11-23 定格：正文默认改为 **W450 静态单实例**（`resources/fonts/MiSans-W450.ttf.gz`，用 fontTools 的 instancer 把字重钉死在 450，没有变异轴），注册为 `MiSans`；完整可变字体另注册为 `MiSans VF`，只给需要粗体的标题用（ui/gui/main.go:92-131、135-145）。字重裁定链：500 Medium 太粗 → 400 回退 → 定格 450。

现状带来的三个事实，写界面代码时要记得：

- 需要 700 的地方必须显式写 `Font(fontMiSansVFFamily)`：侧栏字标、页面标题、hero 标题、任务卡标题。
- 等宽字体是内嵌的 JetBrains Mono VF（OFL 许可，字重轴是标准阶梯，无需手术），调用处写 `Font(fontMonoFamily + ", monospace")`，系统 monospace 兜底。

【待确认】现在嵌入的 `MiSans-VF.ttf.gz` 是第二步手术过的派生版（Medium 380→450）还是原版。`resources/fonts/README.md:17-21` 说是派生版，FONT-PROBE.md 的 macOS 读数（VF 400 与 450 墨水相同）也吻合，但本机 Python 不可用，没能打开字体文件核对。

**清晰度的两条定案**（2026-11-23，都是用户反馈「字发糊」后查出来的）：

- **文字禁半透明。** 不透明度小于 1 的文字元素被按 alpha 叠加渲染，ClearType 的亚像素彩色边缘被冲淡成灰雾；不透明文字走亚像素定位，天然锐利。主犯是各工具页提示行的「灰字 + 半透明 + 小字」三重软化，已全部去掉不透明度。次级文字用 `TextMuted` 色阶表达，不用透明度。现在还用不透明度的只有图标、水印和动画渐显（清单行尺寸的悬停淡出）。
- **正文字号 13 起步。** MiSans VF 没有 hinting 表，深色底上 ClearType 的彩色噪点明显，12px 的小字最敏感，三者叠加致小字发虚。字号整体上调一档（187 处）；新代码正文用 13，10 / 11 只限微型注脚。副标、提示、体积标签按设计仍是 12（AGENTS.md:364、367）。

**字体渲染对照表** `ui/gui/FONT-PROBE.md`：macOS 一列已实测填好，Windows 一列留空待填（本机未跑）。探针 `TestFontProbe` 默认跳过，置 `ZPACK_GUI_FONT_PROBE=1` 才跑。

**Windows 图标全出血**（2026-11-22 用户定案「改动不得影响 mac / linux」）：Windows 任务栏 / 标题图标用撑满画布的 `icon-windows.png`（mac 留白版在任务栏里显小一圈），经 `Dock.SetIcon` 施加；exe 级图标是 `winres.rc` 里资源 ID 1 的 `icon-windows.ico`，用 windres 铸成 `resource_windows_amd64.syso`（文件名带 `_windows_amd64` 后缀，只有 Windows 构建消费）。重生成命令：`export PATH="/c/msys64/ucrt64/bin:$PATH"; cd ui/gui && windres --use-temp-file -O coff -o resource_windows_amd64.syso winres.rc`（裸跑会报 preprocessing failed，windres 要 gcc 在 PATH 里）。

**标题条高度按平台**（2026-11-22 用户反馈「按钮高得夸张」）：macOS 52 是红绿灯的锚定高度；Windows 原生标题栏 32pt，用 52 会把最小化 / 最大化 / 关闭拉成巨钮，所以用 36。

### 6.7 刻录页规则的设计理由

- **只拦明确认识的状态**。三个平台的 `status` 来源不同：Windows 引擎报全部 9 种（含 `unrecognized`）；macOS 有盘时报空串、没盘报 `no-media`；Linux 是 xorriso 短语归一后的值，认不出的原样透传。按状态拦就会误拦 mac / Linux，所以认不出的一律交给引擎裁决（ui/gui/burnstate.go:3-7；AGENTS.md 铁律 5）。
- **任何异常状态都不得走到写入**。此前镜像直烧路径在状态异常的盘上会直接调到写入，现在是主按钮置灰并写明原因（AGENTS.md 铁律 5；specs/burn.md 6.5）。
- **光盘名称属于最后一个区段**（2026-11-24 用户定案）。空白盘随意起；已有内容的盘缺省沿用盘上名称；已封盘不能改。所以名称行只在空白盘（或计划先擦空）时出输入框，其余状态一句话说明——不摆一个灰掉的输入框（ui/gui/burnname.go:9-11；specs/burn.md 6.6）。
- **「先擦空再烧」只对可擦写介质出现**：一次性盘物理不可擦，摆出来只会让人困惑；DVD+RW 天生覆盖写、免擦，也不显示（ui/gui/main.go:5807-5820）。
- **速度用滑杆不用自由输入**：真实用途是降速换老设备兼容，七档够用（自动 / 4 / 8 / 16 / 24 / 32 / 48）。
- **「可追加」由「U 盘模式」正名**：多区段做不到 U 盘承诺的可删改，名不副实；`live` 模式各平台都没接入，GUI 不提供（ui/gui/DESIGN.md:125；ui/gui/main.go:5722-5734）。
- **引导行放不下才换行**的先例就在这一页（三个按钮）。
- 三条规则都是纯函数（`burnstate.go`、`burnname.go`、`burnArguments`），表驱动单测守着；界面层只负责把选中的设备状态喂进去。
- **镜像写进有数据的盘只提醒不拦**（规则四，2026-11-24 用户拍板）。拦截能防误操作，但也拦住了想故意这么刻的人；提醒放在主按钮上方、点下去之前——刻录不可逆，事后在任务卡上看到就晚了。macOS 判不出盘上有没有数据时不出这一行：宁可不说，也不说一句可能是错的话。

### 6.8 右键菜单：设计与陷阱

**双轨并存**（AGENTS.md:381-385）：

| 轨 | 入口脚本 | 产物 | 特点 |
|---|---|---|---|
| 快速操作 | `ui/right-click/macos/quickaction.sh` | `~/Library/Services/` 下的三个工作流：zpack 压缩 / 解压 / 测试 | 免签名、立即生效；结果用系统通知回报；出现在 Finder 右键的「快速操作 / 服务」里 |
| FinderSync 扩展 | `ui/right-click/macos/build-xcode.sh` | `/Applications/zpack Finder Menu.app`（宿主 + 扩展 + 内嵌引擎 + 两套图标） | 一级菜单「zpack ▸」带图标；需 Apple Development 证书（免费 Apple ID 即可）；有进度窗与结果窗 |

**FinderSync 的架构是三次失败后定下来的**（据 AGENTS.md:384、388，mac 实测）：

- 在沙箱扩展进程里直接起 `zpack` 干活——**死路**：写用户目录被拒，而且扩展进程没有界面权限，弹不出对话框。仓库里还留着一套这么做的 Objective-C 实现（`src/ZpackSync.m` + `build.sh`），它把结果改用 osascript 系统通知回报，但沙箱的限制还在。
- 给宿主传参也不行：`NSWorkspace.OpenConfiguration.arguments` 从沙箱扩展发起时会被静默丢弃，回调还谎报成功；自定义 URL scheme 的 GURL 事件在 macOS 26 上冷 / 热启动都不送达。
- 结论：**扩展 → 宿主只信两个原语——文件读写与进程启动**。现在的分工：

| 角色 | 沙箱 | 职责 |
|---|---|---|
| 扩展（`zpackSync.appex`） | 是，硬化运行时 | 只构建菜单、给选中项分类；动作 = 把 `{verb, paths}` 写进自己容器里的 `zpack-job.json`，再不带参数地拉起宿主 |
| 宿主（`zpack.app`，装成 `zpack Finder Menu.app`） | 否 | 轮询任务文件（每 0.1 秒，最多 5 秒），取单即删，跑内嵌的 `zpack`，弹进度窗；干完一单就退出 |

- **宿主一单一命**：常驻实例会把下一次启动退化成「激活」，参数、事件、任务文件轮询窗口全都错过。所以裸启动 5 秒没有任务就退出。
- **选中项快照**：菜单构建时把选中路径存下来——动作触发时菜单已关，再去取选中项可能拿不回。

**进度窗**（`xcode/zpackFinderMenu/JobWindow.swift`）：

- 输入不小于 64MiB 才显示进度条（小任务秒级完成，进度条只会闪一下）。
- 运行态：标题 + 进度条 + 明细 + 「取消」。完成态：标题 + 摘要 + 两个对钩 + 「确定 (N)」。
- 两个对钩「完成后打开文件夹」「完成后自动关闭」记在 `UserDefaults`（键 `jobWindow.openFolderAfterDone` / `jobWindow.autoCloseAfterDone`），缺省打开文件夹关、自动关闭开。
- 成功后「确定」带 5 秒倒计时；回车即确认；失败不倒计时（用户要读原因）。点「确定」也尊重「打开文件夹」对钩。
- 窗口是自建的非模态 `NSWindow`（不是 `NSAlert`），浮在最前。AGENTS.md:384 记的「模态 + 次要钮 + stopModal」是更早的 `NSAlert` 版交互，已被这版取代。
- **弹窗聚焦**：启动完成时就把激活策略升为 regular（临到弹窗才升，窗口服务器来不及登记）；弹窗时 `activate(ignoringOtherApps:)` + `makeKeyAndOrderFront` + 浮层级别。

**压缩命名**：输出钉在首路径的同目录，包名 = 首路径去扩展名（`照片.jpg` → `照片.zip`，绝不 `.jpg.zip`）；多选时所有路径打进同一个包；同名不覆盖，自动序号 `照片 2.zip`（`xcode/zpackFinderMenu/MyApp.swift:310-335`）。解压则把工作目录切到首路径的父目录，走 CLI 的智能解压（`MyApp.swift:148-155`）。

**三层图标**（2026-11-21 用户两轮定案，AGENTS.md:383）：

| 用途 | 文件 | 样子 |

**陷阱清单**（据 AGENTS.md:388-396，全部 mac 实测；对应逻辑已固化在 `build-xcode.sh`）：

- **同一个扩展 ID 注册了多个副本 = 右键消失 / 图标没了的元凶。** Xcode 图形界面构建会把 DerivedData 下的产物登记进 LaunchServices，而 `pkd` 每次 Finder 重启都与 LaunchServices 重新同步——只 `pluginkit -r` 拔不干净，重启后旧副本又被捞回来当选。正解是两处一起处理：其它宿主全部 `lsregister -u`，真身的宿主与扩展都 `lsregister -f`，再 `pluginkit -a` 真身。`build-xcode.sh` 收尾做四项验收：LaunchServices 名下只剩真身 / Finder 重启后当选路径连查两次稳定 / 真身封印完好 / 扩展已启用。
- **已签名包内的文件禁止原地替换**（禁止手工 `cp`）。哪怕只是换一个 `Resources/zpack`，封印也会失效；Finder 宿主带硬化运行时，封印一坏系统就弃用真身、退回别处注册的旧副本——2026-11-23「右键图标又没了」就是这个原因。刷新引擎必须用 `ui/right-click/macos/refresh-engine.sh`：拷进引擎、清资源叉、重签、校验。GUI 本体的 `install.sh` 同理（引擎是在 mygo 签名之后才注入的）。
- **扩展手动签名必须带 `--options runtime`**：裸签会抹掉硬化运行时，macOS 26 的 pluginkit 拒载。签名顺序先扩展后外壳。
- **资源叉会让 codesign 拒签**：`bin/zpack` 带着 Finder 自定义图标，拷进包后要 `xattr -cr`（只清拷贝件，原件不动）。
- **扩展注册走 pluginkit，与宿主进程无关**，不要裸 `open` 宿主（它会常驻并吞掉下一单）。
- **全新 xcodebuild 产物的扩展包里没有 Resources 目录**，拷图标前必须先建目录（历史上是靠增量构建的残留才没出事）。
- **诊断三连**：`pluginkit -mAvv -i <扩展 ID>` 看当选路径是不是 `/Applications` 下的真身 → `codesign --verify --deep --strict` 看封印 → `lsregister -dump` 看有没有旧宿主。扩展里写文件探针到自家容器（统一日志在扩展里不可靠），宿主可以写 `/tmp`。

**快速操作轨的两个工程点**（AGENTS.md:382）：工作流文件必须克隆真样例模板再用 plistlib 改参数（`COMMAND_STRING`、`inputMethod=1`），手写的 `source` + `inputAsArguments` 是不执行的老参数集；解压前要先 `cd` 到归档所在目录——智能解压的落点相对于服务进程的工作目录，而不是归档目录。

### 7.4 构建与打包

**构建 GUI**（在 `ui/gui/` 目录下；构建命令由 `go.mod` 的 `tool` 指令提供）：

```bash
go tool mygo build                                                   # 只构建当前平台
go tool mygo build -platform darwin/universal,linux/amd64,windows/amd64   # 跨平台（mygo 不需要 cgo）
go tool mygo build -skip-installer                                   # Windows 上不出安装器
```

产物都在 `ui/gui/build/<平台>-<架构>/` 下，不入库（仓库根 `.gitignore:27-30`）。形态按 mygo v0.10.0 的构建说明（模块缓存里的 `cmd/mygo/build.go`）：

| 平台 | 产物 | 本机现状 |
|---|---|---|
| macOS（arm64） | 签名后的 `zpack.app` + `zpack-<版本>-<架构>.dmg` | `install.sh` 取 `build/darwin-arm64/zpack.app`；签名与打包磁盘镜像要在 macOS 上做 |
| Windows（amd64） | `zpack.exe` + 安装器 `zpack-setup-<版本>-amd64.exe` | 本机实测：主程序约 33MB、安装器约 45.5MB；同目录另有 `fonts/`、三个图标文件和清单 `.mygo-files` |
| Linux | 可执行文件 + `zpack-<版本>-linux-<架构>.tar.gz`（内含装到 `~/.local` 的 `install.sh`）+ deb / RPM / PKGBUILD | 没构建过 |

**`resources/` 目录会随包分发**。mygo 把项目里名为 `resources/` 的目录整体当作随包资源：macOS 上拷进 `.app/Contents/Resources`，其它平台拷到可执行文件旁边；其中按平台命名的子目录（`resources/darwin`、`resources/windows-amd64` 这样的）只随对应平台的包走（mygo `cmd/mygo/resources.go:21-27`）。所以 Windows 产物旁边多出来的 `fonts/` 与图标，是 `ui/gui/resources/` 的分发副本——内容与 `go:embed` 进二进制的一样，GUI 代码运行时并不读它们（全包没有用到 `mygo.PathResources`），只是因为目录叫 `resources` 才被带上。

**mac 装机**：`bash ui/gui/install.sh`（ui/gui/install.sh:14-33）。

1. `go tool mygo build`。
2. 要求仓库的 `bin/zpack` 存在且可执行，否则中止。
3. 把引擎拷进 `.app/Contents/Resources/zpack`，`xattr -cr` 清掉资源叉，adhoc 重签并校验——引擎是在 mygo 签名之后才注入的，不重签封装出来的包封印是坏的。
4. 删掉旧的 `/Applications/zpack.app`，`ditto` 新包过去，再校验一次。

装机后 GUI 自己带着引擎（查找顺序第 3 项命中），安装包自包含。App 的正名是 `zpack`；Finder 宿主让位改叫 `zpack Finder Menu.app`（ui/gui/install.sh:4-7）。

**刷新引擎**：引擎代码动过之后，`bash ui/right-click/macos/refresh-engine.sh` 把新铸的 `bin/zpack` 换进两个装机位并重签——GUI 本体 adhoc 签名；Finder 宿主用 Apple Development 证书 + 硬化运行时重签，所以这台机器的钥匙串里必须有证书。脚本最后还会检查扩展当前生效的路径是不是 `/Applications` 下的真身（ui/right-click/macos/refresh-engine.sh:20-45）。

**Windows**：仓库里只有 `go tool mygo build` 的产物，没有引擎注入或装机步骤，安装器里不含引擎（3.2）。`resources/windows-amd64/` 这样的按平台资源目录是现成的随包分发通道，但目前没用上；即便用上也有两个障碍——引擎与 GUI 的可执行文件同名 `zpack.exe`，且查找顺序里没有对应的候选（9.2 第 1 条）。

**右键菜单**：`bash ui/right-click/macos/build-xcode.sh`（首次、改了扩展或图标之后）；`bash ui/right-click/macos/quickaction.sh`（想要免签名的快速操作时）；`python3 ui/right-click/macos/gen-menu-icon.py`（改了菜单图标比例时）。没有卸载脚本。

### 8.2 怎么跑

```bash
cd ui/gui
go test .                                   # 全套
go test -race .                             # 查数据竞争（体积缓存的竞争就是这样查出来的）
ZPACK_GUI_FONT_PROBE=1 go test -run TestFontProbe -count=1 -v .   # 字体探针，产物落 build/fontprobe/
```

- 必须进 `ui/gui` 目录跑：它是独立 module，仓库根目录的 `go test ./...` 不包含它。
- 首次需要下载 mygo 模块。`proxy.golang.org` 不可达的机器上加 `GOPROXY=https://goproxy.cn,direct`（AGENTS.md:403）。
- Windows 上 Go 不在 PATH 时先 `export PATH="/c/Program Files/Go/bin:$PATH"`（ui/gui/FONT-PROBE.md:19）。
- 三个标了「需真实引擎」的用例直接调 `Service{binary: 引擎}`，跑仓库的 `bin/zpack(.exe)`，只写测试临时目录；没有这个文件就跳过。其余用例一律不执行引擎——用 `ZPACK_BIN` 指向一个替身文件，或预设状态绕开枚举。

跑测试、写测试时要知道的坑（详见 6.6）：无头环境没有主循环，`RunOnMain` 永远等不到；`Release` 会触发点击，写剪贴板的元素一点即死锁，所以矩阵只 `Press`；刻录页测试必须预设 `burnQueried = true`；渲染页面函数要经 `heroAwarePage`；反馈矩阵要把页面单独渲染、窗口拉到 1100 高、比较前拷贝帧。

### 8.3 手动验证

没有自动化覆盖、只能上真机看的：

- **引擎缺失提示**：`ZPACK_BIN` 指向一个不存在的路径启动，点任意主按钮应弹「未找到 zpack 引擎」，设置页引擎路径行是红字。
- **外观三态**：设置页切深色 / 浅色 / 跟随系统，界面立即变；重启后保持；手动把 `gui-settings.json` 改坏后启动应回退跟随系统。
- **任务全程**：压一个大目录，看进度条与明细、点取消看半成品是否清掉、断网或给一个无权限目录看失败 toast。
- **字体与图标**：Windows 上看任务栏 / 标题图标是否撑满、最小化 / 最大化 / 关闭三钮是否为原生比例。
- **刻录页**：无光驱机器上应显示「未检测到刻录机」、主按钮「未检测到刻录机」置灰；有光驱时逐个状态对照 2.6 的三张表。
- **右键菜单**（mac）：`build-xcode.sh` 自带四项验收；装好后到 Finder 对归档、普通文件、混合选择各右键一次，核对菜单项；做完一单看进度窗的倒计时、回车确认、两个对钩是否记忆；出意外按 6.8 的诊断三连查。

## 9. 未结项与已知限制

### 9.1 没做的

- **Windows Explorer / Linux 文件管理器的右键菜单**：`ui/right-click/` 下只有 `macos/`。
- **GUI 没接的 CLI 命令**（见 1.2）与**没暴露的旗标**（见 3.3 最后一列）。比较显眼的有：压缩的 `--exclude` / `--jobs` / `--temp-dir` / `--comment`，解压的 `--force` / `--jobs` / `--password-table`，刻录的 `--close` / `--no-eject`，视频的 `--preset` / `--screen` / `--codec`，`hash` 的 `--output` / `--check` 与 `sha224`。
- **参数记忆**：除外观外什么都不记（缺省格式 / 级别 / 分卷 / 完成后策略 / 各页选项都在重启后回到缺省）。
- **设置页的其余条目**：DESIGN.md §1.5 规划的缺省格式与级别、默认输出目录、`.zpackignore` 说明、Finder 扩展状态检测、文件关联、并行任务上限、临时目录，都没做。
- **归档浏览**只做了「列清单 + 校验」：没有解压入口、密码框、过滤、目录树、预览、虚拟滚动，清单只显示前 500 条。
- **桌面模式**：Dock 拖放压缩、悬浮窗（DESIGN.md §0、§2 的 M3）。
- **Windows / Linux 的装机闭环**：Windows 的安装器不含引擎，也没有引擎注入步骤（9.2 第 1 条）；Linux 从没构建过、没跑过。右键菜单没有卸载脚本（卸载要手工：删 `/Applications/zpack Finder Menu.app`，`pluginkit -r` 与 `lsregister -u` 注销，重启 Finder；快速操作删 `~/Library/Services/zpack *.workflow`）。
- **GUI 的脚本门禁**：`verify-gui.sh` 没有落地。
- **字体对照表的 Windows 一列**没填（`ui/gui/FONT-PROBE.md`）。

### 9.2 已知限制与代码里观察到的问题

按影响从大到小。标「推出」的是从代码读出来、没有在真机上复现的。

1. **Windows 装机后 GUI 找不到引擎**（3.2）：同目录候选恒被自体防护跳过，安装器里不含引擎，仓库里也没有 Windows 侧的引擎注入步骤。在仓库目录里直接跑 `ui/gui/build/windows-amd64/zpack.exe` 是能用的（向上找到仓库的 `bin/zpack.exe`），装到别处就不行。
2. **macOS / Linux 上光盘名称永远填不了**。`planBurnVolumeName` 只在 `status == "blank"` 或勾了擦除时出输入框，而这两个平台的引擎在有盘时不报 `blank`（macOS 报空串）。除非盘是可擦写且勾了「先擦空再烧」，名称行恒为「需空白光盘 / 放入空白光盘后可以设置名称」——盘其实在光驱里（ui/gui/burnname.go:31-43；ui/gui/burnstate.go:4-5）。
3. **选了「加密」但密码框留空，产出的包不加密**，界面没有任何提示（4.6）。
4. **取消的清理范围**：只有压缩任务登记了清理；其它任务被杀后可能留半截产物。「杀进程后不等进程退出就删文件」的时序问题已修（3.5、6.6）。删除出错仍被忽略（ui/gui/service.go:169-177）：Windows 上若有别的程序短暂占着刚写出的归档（如杀毒软件在扫描），那一次删除会落空、留下半成品——这种情况没有实测过，遇到再说。
5. **GUI 解压不走智能解压**（2.5）：恒传 `--output`。
6. **擦除开关的状态不随所选设备重置**。`burnBlank` 只由那个开关写入（ui/gui/main.go:5817），而开关只在可擦写介质上出现；在某台可擦写设备上打开后换选另一台，开关不见了但值还在，`burnBlockReason` 会按「勾了擦除」放行，`--blank` 也会照传，交给引擎裁决（推出）。
7. **刻录完成后设备状态不会自动刷新**：括注、名称行、拦截都停留在枚举那一刻，要点「刷新」。
8. **「完成后」策略对全部任务生效，但控件只在压缩台与解压台**（4.2）。
9. **没有进度行的任务进度条停在 0%**（3.5）：媒体、图片、PDF、Office、7z 压缩、刻录。
10. **任务并发没有上限**：点多少次起多少个子进程。
11. **文件夹拖到单文件转换页拦不住**，要到处理台才报错（4.6，推出）。
12. **图片压缩按扩展名数 JPG**（ui/gui/main.go:3292-3298），与格式守卫「只看内容不看扩展名」的原则不一致；警告条和主按钮的可用性都可能被改过扩展名的文件骗过。
13. **解压台与归档浏览的 toast 靠 `error_info` 的子串匹配**（3.4），引擎改文案就会失效。
14. **几处例外于「不截断」规则**：处理台任务标题单行省略（标题是文件基名，ui/gui/main.go:4824-4825）；参数校验的红字单行省略 + 悬停提示（ui/gui/main.go:2068-2069）；字符集摘要过长省略（ui/gui/main.go:4248）。
15. **同名序号试到 9998 就原样返回**，会覆盖（ui/gui/service.go:454-467）。
16. **密码经 argv 传给引擎**（3.1），压缩 / 解压期间在进程列表里可见。
17. **Finder 右键（Swift 版）的几个问题**（读代码得出，未在 mac 上复现）：
    - 菜单项动作把**整份选中清单**交给宿主（`xcode/zpackSync/FinderSync.swift:98-124`），而引擎的 `extract` 与 `test` 只取第一个位置参数（`cli/archive/extract.go:103-106`、`cli/archive/list.go:46-61`）。多选时「解压到此处」「测试归档」只处理第一个；混合选择时第一个若不是归档就直接失败。菜单分类时算好的「归档 / 非归档」两组没有传给动作。
    - 构建菜单时对**每个**选中的非目录文件同步起一次 `zpack list`，没有上限（`FinderSync.swift:45-50`、`86-94`）；被取代的 Objective-C 版有 20 个的探测上限（`src/ZpackSync.m:9`、`80`）。
    - 扩展里的引擎查找有一个写死的开发机路径 `~/WebstormProjects/zpack/bin/zpack`（`FinderSync.swift:25`）；宿主则只认自己 bundle 里的引擎（`MyApp.swift:338-344`）。
    - 宿主里还留着 GURL 与 `--zpack-job` 两条通道（`MyApp.swift:44-51`、`67-72`、`107-125`），注释与 AGENTS.md「GURL 不可达、任务文件才是主通道」的结论互相矛盾；另有一个没人调用的 `extractField`（`MyApp.swift:347-357`）。
    - 宿主的体积写法是 `2.3 MB`（带空格、一位小数，`MyApp.swift:228-237`），与 GUI 的 `2.3MB`（4.5）不一致。
18. **第一代 Objective-C 版右键菜单仍留在仓库里**（`build.sh`、`src/`），与现行的 Xcode 版并存，文档没有说明它的去留。【待确认】是否已废弃、可否删除。
19. **`main.go` 单文件 5856 行**，24 个页面与全部小件都在里面；压缩台与解压台各自内嵌了一份设置行闭包（ui/gui/main.go:1202-1222、1714-1723），与公共的 `openSettingRow` / `openSettingRowTop` 重复。
20. **页面代码里仍有内联的悬停 / 按下判断**，违反「反馈语汇只有一处定义」：压缩台与解压台的密码眼睛钮（ui/gui/main.go:1383-1387、1777-1781）、`toolSegmented` 未选中段（1830-1834）、Base64 历史卡删除钮（2638-2642）、图片预览画框（2749-2753）、图片压缩策略单选行（3310-3324）。
21. **Windows 上「可追加」的提示写的是尚未实现的能力**（「后续将支持真 UDF 优盘式」，ui/gui/main.go:5728）。
